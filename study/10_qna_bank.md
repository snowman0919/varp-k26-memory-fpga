# 예상 질문과 답변

총 89문항이다. 먼저 짧게 답하고, 필요할 때 근거 파일과 주의할 해석을 덧붙인다.

## Q01. 연구의 한 문장 질문은?

- **짧은 답:** K26 계산부와 외부 Memory FPGA를 결합할 가치가 있는 조건, 그리고 작업 훔치기가 그 구조의 유휴 연산을 줄이는 조건을 묻는다.
- **상세 답:** Gemma 3 1B를 의존성 있는 TileJob으로 바꾸고, K26 로컬 기준선·초기 배치·큐 정책·원격 이동 비용을 함께 비교한다.
- **근거:** `paper/final/submission_manuscript.md — “I. 서론”, “VIII. 결과와 시스템 설계 결정”`
- **주의할 해석:** ‘외부 FPGA가 빠르다’로 바꾸면 보드 증거를 과장한다.

## Q02. 왜 단순히 ‘메모리 대역폭이 중요하다’는 말보다 진전인가?

- **짧은 답:** 병목을 대기열 정책과 검증 가능한 지표로 바꿨기 때문이다.
- **상세 답:** 실제 그래프 기반 작업, p95/p99, 원격 전송량, 정확히 한 번 처리 조건과 다음 물리 관문을 연결했다.
- **근거:** `paper/final/submission_manuscript.md — “I. 서론”, “II. 관련 연구와 연구 공백”`
- **주의할 해석:** 알고리즘 신규성이나 최고 성능으로 과장하면 안 된다.

## Q03. 핵심 기여 세 가지는?

- **짧은 답:** 역할 분리 구조, 이동 비용을 포함한 동적 작업 배치, 모델→RTL→KiCad 재현 흐름이다.
- **상세 답:** K26의 연산·제어와 Memory FPGA의 다채널 가중치 공급을 분리하고, 의존성·초기 배치·원격 서비스 비용을 포함해 정책을 비교했으며, 실제 타일의 논리 RTL 폐루프와 참조 라우팅 쿠폰까지 연결했다.
- **근거:** `paper/final/submission_manuscript.md — “I. 서론”`
- **주의할 해석:** 완성 시스템 구현을 기여로 추가하면 과장이다.

## Q04. 이 연구는 완성된 가속기인가?

- **짧은 답:** 아니다.
- **상세 답:** 작업 수락→DMA 요청→논리 메모리 응답→논리 링크 FIFO→작업 ID 결합→MatVec 결과의 RTL 경로는 닫혔다. 다만 GTH 직렬화, 클록 도메인 교차·크레딧, 실제 MIG/DDR 타이밍과 보드 계측은 아직 없다.
- **근거:** `docs/architecture.md`
- **주의할 해석:** 논리 폐루프를 물리 GTH–DDR 폐루프 또는 보드 구현으로 확대하면 안 된다.

## Q05. 어떤 증거 유형이 있는가?

- **짧은 답:** 직접 확인, RTL 시뮬레이션, 그래프 기반, 분석 모델, 미검증이다.
- **상세 답:** 각 유형은 지원 가능한 주장과 금지 주장을 표 2에서 고정한다.
- **근거:** `docs/evidence.md; paper/final/submission_manuscript.md — “IV. K26–Memory FPGA 시스템 구조”, 표 2`
- **주의할 해석:** 유형을 생략하면 분석값이 실측처럼 들린다.

## Q06. 결론을 한 문장으로 말하면?

- **짧은 답:** S3는 불균형 조건의 후보이며 외부 메모리 채택은 실측 기준선까지 보류한다.
- **상세 답:** 편향·혼합 부하의 꼬리 지연·전송량 이득은 분석 모델 결과이며 용량만으로 8 GiB 필요성을 지지하지 않는다.
- **근거:** `paper/final/submission_manuscript.md — “VIII. 결과와 시스템 설계 결정”, “IX. PCB 인터페이스 라우팅 쿠폰”`
- **주의할 해석:** ‘S3 채택 확정’으로 말하지 않는다.

## Q07. 증거 경계를 왜 함께 제시하는가?

- **짧은 답:** 연구의 중심 기여는 아니지만 분석·RTL·물리 쿠폰의 효력을 구분하기 위해서다.
- **상세 답:** 그래프, RTL, 분석 모델, 물리 제안의 연결 여부를 명시해 다음 실험을 선택할 수 있다.
- **근거:** `docs/evidence.md`
- **주의할 해석:** 한계를 단순한 미완성 변명으로 축소하지 않는다.

## Q08. 가장 중요한 다음 실험은?

- **짧은 답:** 동일 Gemma 작업으로 K26 로컬 메모리 기준선을 보드에서 먼저 측정하는 것이다.
- **상세 답:** 그 다음 GTH, 클록 도메인 교차, 크레딧, 패킷과 MIG를 논리 폐루프에 붙이고, 정확성·유효 대역폭·꼬리 지연·전력을 로컬 기준선과 같은 조건에서 측정한다.
- **근거:** `docs/architecture.md`
- **주의할 해석:** 바로 보드 성능 수치를 약속하지 않는다.

## Q09. Prefill이란?

- **짧은 답:** 입력 문맥을 처리해 KV cache를 만드는 단계다.
- **상세 답:** 여러 토큰을 병렬 계산할 여지가 크고 Attention의 행렬 연산 형태가 Decode와 다르다.
- **근거:** `study/04_glossary.md`
- **주의할 해석:** 본 결과를 prefill 성능으로 확대하지 않는다.

## Q10. Decode란?

- **짧은 답:** 이전 KV를 사용해 다음 토큰을 순차 생성하는 단계다.
- **상세 답:** 작은 배치에서는 투영 가중치를 반복 전송하므로 메모리와 대기열의 꼬리 지연이 중요해진다.
- **근거:** `paper/final/submission_manuscript.md — “I. 서론”, “III. 온디바이스 가속기의 설계 목표”`
- **주의할 해석:** decode-32와 context-32K를 혼동하지 않는다.

## Q11. Decode-32와 context-32K의 차이는?

- **짧은 답:** 32개 생성 토큰과 KV 길이 32,768의 차이다.
- **상세 답:** Decode-32는 의존성 있는 802 TileJob/토큰을 32번 직렬 반복한 25,664 TileJob이고, context-32K는 KV와 실행 여유를 포함한 용량 산술 조건이다.
- **근거:** `paper/final/submission_manuscript.md — “III. 온디바이스 가속기의 설계 목표”, “V. Gemma 3 1B 작업의 하드웨어 매핑”`
- **주의할 해석:** 둘을 같은 부하 길이로 말하면 계산 의미가 바뀐다.

## Q12. 투영 작업 부하는 무엇인가?

- **짧은 답:** Attention과 MLP의 선형변환 작업이다.
- **상세 답:** q/k/v/o 104, gate/up/down 78, lm_head 1로 토큰당 183개다.
- **근거:** `paper/final/submission_manuscript.md — “V. Gemma 3 1B 작업의 하드웨어 매핑”`
- **주의할 해석:** 전체 ONNX 노드가 모두 투영이라고 말하지 않는다.

## Q13. MatVec는 무엇인가?

- **짧은 답:** 행렬 타일과 벡터의 곱이다.
- **상세 답:** 현재 RTL 연산 모듈은 부호 있는 INT8 16×4 입력을 INT32 누산 결과로 계산한다.
- **근거:** `paper/final/submission_manuscript.md — “V. Gemma 3 1B 작업의 하드웨어 매핑”; hw/src/main/scala/varp/compute/ComputeCluster.scala; hw/src/main/scala/qk/DecodeMatVecInt8.scala`
- **주의할 해석:** 전체 투영 연산기나 모델 실행으로 확대하지 않는다.

## Q14. 타일 분할이 필요한 이유는?

- **짧은 답:** 큰 투영을 제한된 연산·메모리 단위로 나누기 위해서다.
- **상세 답:** TileJob이 K/N 범위, 주소와 선호 채널·링크 묶음을 보존한다.
- **근거:** `paper/final/submission_manuscript.md — “V. Gemma 3 1B 작업의 하드웨어 매핑”`
- **주의할 해석:** 현재 타일 시험 입력이 전체 배치를 검증했다고 말하지 않는다.

## Q15. INT8과 INT4의 차이는?

- **짧은 답:** 가중치 비트폭과 표현 범위가 다르다.
- **상세 답:** INT4는 저장·전송량을 더 줄일 수 있지만 묶음 배치, 스케일, 정확도와 RTL 데이터 경로 검증이 별도로 필요하다.
- **근거:** `paper/final/submission_manuscript.md — “V. Gemma 3 1B 작업의 하드웨어 매핑”; study/04_glossary.md`
- **주의할 해석:** 이 연구 자료가 INT4를 구현했다고 말하지 않는다.

## Q16. 실제 타일 결과 일치 3/3은 무엇을 증명하는가?

- **짧은 답:** 세 실제 16×4 가중치 타일의 RTL 산술 일치를 증명한다.
- **상세 답:** 외부 데이터 오프셋에서 읽고 타일별 대칭 INT8로 양자화한 값이 INT32 기준 결과와 일치했다.
- **근거:** `paper/final/submission_manuscript.md — “V. Gemma 3 1B 작업의 하드웨어 매핑”`
- **주의할 해석:** 모델 전체 정확도나 K26 타이밍을 증명하지 않는다.

## Q17. ONNX 그래프 노드 수는?

- **짧은 답:** 7,837개다.
- **상세 답:** 해시로 고정한 연구 자료의 protobuf 그래프 목록에서 얻은 그래프 기반 수치다.
- **근거:** `paper/final/submission_manuscript.md — “V. Gemma 3 1B 작업의 하드웨어 매핑”`
- **주의할 해석:** 다른 모델 버전에 일반화하지 않는다.

## Q18. 토큰당 투영 수는?

- **짧은 답:** 183개다.
- **상세 답:** Attention 104, MLP 78, lm_head 1의 합이다.
- **근거:** `paper/final/submission_manuscript.md — “V. Gemma 3 1B 작업의 하드웨어 매핑”`
- **주의할 해석:** 실제 가속기가 183개를 실행했다는 뜻은 아니다.

## Q19. 모델 가중치가 저장소에 있는가?

- **짧은 답:** 없다.
- **상세 답:** 목록, 해시와 획득 안내서만 공개하며 가중치는 릴리스에서도 제외한다.
- **근거:** `models/ACQUISITION.md; models/LICENSE_NOTES.md`
- **주의할 해석:** 재배포 권한이 있다고 암시하지 않는다.

## Q20. 183개 투영과 802개 TileJob의 차이는?

- **짧은 답:** 투영은 그래프 연산 단위이고 TileJob은 하드웨어가 처리할 K/N 타일 단위다.
- **상세 답:** 토큰당 밀집 투영 183개를 N≤1024와 전체 K 범위의 작업으로 나누면 802 TileJob이 된다. 최종 결론은 구형 호스트 지연값에 기대지 않는다.
- **근거:** `paper/final/submission_manuscript.md — “V. Gemma 3 1B 작업의 하드웨어 매핑”; results/model_level/gemma3_1b_dependency_manifest.json`
- **주의할 해석:** 투영 수를 실행 작업 수로 그대로 사용하지 않는다.

## Q21. TileJob의 핵심 필드는?

- **짧은 답:** 작업 식별자, 범위, 주소, 지역성과 소유권 정보다.
- **상세 답:** 작업 ID, 도착 시점, 계층·연산, 활성값·가중치·출력 주소, K/N, 선호 채널·링크 묶음, 우선순위, 이동 가능 표시를 가진다.
- **근거:** `paper/final/submission_manuscript.md — “IV. K26–Memory FPGA 시스템 구조”`
- **주의할 해석:** Python 모델과 RTL의 소유권 정의가 완전히 같다고 말하지 않는다.

## Q22. 연산 경로의 닫힌 구간은?

- **짧은 답:** 작업 수락→DMA 요청→논리 응답→논리 링크 FIFO→작업 ID 결합→MatVec 결과다.
- **상세 답:** `ClosedLoopVirtualPrototypeTop`은 실제 Gemma INT8 타일 세 개에 대해 DMA 응답 뒤에만 계산을 시작하고 INT32 기준 결과까지 작업 식별자를 보존한다.
- **근거:** `docs/architecture.md`
- **주의할 해석:** 논리 응답 주입을 실제 DDR3L 읽기나 GTH 전송으로 부르지 않는다.

## Q23. 메모리 명령 경로는 무엇을 하는가?

- **짧은 답:** 외부 요청을 채널·뱅크 대기열을 거쳐 명령으로 내보낸다.
- **상세 답:** 폐루프 상위 모듈에서는 명령과 작업 ID를 보존한 뒤 시험 응답 경계에서 데이터를 주입한다. 물리 MIG/DDR 제어기와 타이밍은 아직 연결하지 않았다.
- **근거:** `docs/architecture.md`
- **주의할 해석:** 완전한 DDR 제어기나 DMA로 부르지 않는다.

## Q24. 링크 경로는 무엇을 하는가?

- **짧은 답:** 응답 데이터를 선택한 링크 묶음의 논리 FIFO로 전달한다.
- **상세 답:** 폐루프 상위 모듈에서 데이터와 작업 ID가 MatVec까지 이어지지만, GTH 래퍼·패킷 구성·크레딧·클록 도메인 교차는 후속 물리 구현 범위다.
- **근거:** `docs/architecture.md`
- **주의할 해석:** 실제 유효 대역폭을 측정했다고 말하지 않는다.

## Q25. 왜 TileJob 대기열과 전송 FIFO를 분리하는가?

- **짧은 답:** 작업 배치와 바이트 이동의 원인을 분리하기 위해서다.
- **상세 답:** 전자는 실행 소유권, 후자는 크레딧·역압과 전송 시점을 결정한다.
- **근거:** `paper/final/submission_manuscript.md — “IV. K26–Memory FPGA 시스템 구조”`
- **주의할 해석:** 대기열 개선을 링크 개선으로 등치하지 않는다.

## Q26. 역압(Backpressure)이란?

- **짧은 답:** 뒤쪽 단계가 받을 수 없을 때 앞쪽 전송을 늦추는 흐름 제어 현상이다.
- **상세 답:** 현재 논리 경로는 Stream/FIFO의 준비·유효 신호 기반 역압을 구현했다. 물리 링크의 크레딧 흐름 제어와 클록 도메인 교차는 아직 구현하지 않았으며, 작업 대기열 불균형과도 다른 원인이다.
- **근거:** `study/04_glossary.md`
- **주의할 해석:** 논리 FIFO 역압을 물리 GTH 링크의 크레딧·클록 도메인 교차 구현으로 확대하지 않는다.

## Q27. CDC란?

- **짧은 답:** 서로 다른 클록 도메인 사이의 안전한 전달이다.
- **상세 답:** 동기화 회로나 비동기 FIFO와 준안정성 분석이 필요하다.
- **근거:** `docs/architecture.md`
- **주의할 해석:** 단순 FIFO를 클록 도메인 교차 완료로 간주하지 않는다.

## Q28. DDR channel/bank/row의 관계는?

- **짧은 답:** 채널은 독립 인터페이스, 뱅크는 내부 병렬 단위, 행은 뱅크 안에서 열린 데이터 단위다.
- **상세 답:** 주소 매핑과 행 적중 여부가 서비스 시간과 경합을 바꾼다.
- **근거:** `paper/final/submission_manuscript.md — “IV. K26–Memory FPGA 시스템 구조”; study/04_glossary.md`
- **주의할 해석:** 핀 전송률을 유효 대역폭으로 말하지 않는다.

## Q29. 네 채널 대역폭 산술값은?
