## Slide 1: 온디바이스 sLLM을 위한 K26–Memory FPGA 후보 구조 평가 (0:25)

기억할 문장: 이 발표는 완성 제품이 아니라 K26–Memory FPGA 후보 구조의 설계 공간 평가입니다.

발화문: 온디바이스 sLLM에서 가중치를 어디에 두고 어떻게 공급할지를 연구했습니다. K26이 연산과 제어를 맡고 외부 Memory FPGA가 다채널 가중치 공급을 맡는 후보 구조를 만들고, 작업 훔치기(Work Stealing)가 유휴 연산을 줄이는 조건과 그때 생기는 데이터 이동 비용을 함께 분석했습니다. 중심 질문은 어떤 배치와 부하에서 공급 분리의 이득이 이동 비용을 넘어서는가입니다.

그림 설명 순서: 온디바이스 제약 → K26/Memory FPGA 역할 → 채택 조건 질문

전환: 먼저 오늘 답할 질문을 보겠습니다.

예상 질문: 이 연구의 핵심 기여를 한 문장으로 말하면 무엇인가?

답변 핵심: 계산·공급 역할 분리, 이동 비용을 포함한 동적 배치, 모델→RTL→KiCad 재현 흐름이 세 기여입니다.

해석 경계: 후보 구조·분석 결과이며 제작 완료 가속기를 뜻하지 않습니다.

주의할 표현: 완성 제품·실측 가속기라고 말하지 않는다.

## Slide 2: 오늘 답할 네 가지 질문 (0:25)

기억할 문장: 발표는 왜 검토했는지, 무엇을 설계했는지, 무엇을 확인했는지, 언제 채택할지의 순서입니다.

발화문: 첫째 외부 메모리 구조를 왜 검토했는가, 둘째 계산부와 가중치 공급부를 어떻게 나눴는가, 셋째 실제 Gemma 작업에서 무엇을 검증했는가, 마지막으로 어떤 조건에서 구조와 작업 훔치기가 유효한가를 답하겠습니다.

그림 설명 순서: 필요성 → 구조 → 검증 → 채택 조건의 네 번호

전환: 출발점은 예상과 달랐던 용량 계산입니다.

예상 질문: 왜 이 네 질문 순서로 발표하는가?

답변 핵심: 필요성에서 시작해 구조와 검증을 거친 뒤 채택 조건으로 끝내야 결과가 설계 결정으로 연결됩니다.

해석 경계: 세부 조건은 발표자 노트와 출처 인덱스에 있습니다.

주의할 표현: 목차를 결과처럼 설명하지 않는다.

## Slide 3: 1B는 4GB에 들어갔다—연구 질문을 바꿨다 (0:45)

기억할 문장: Gemma 1B의 2.43 GiB가 K26 4GB 안에 들어가므로 외부 메모리는 기본 요구가 아니라 조건부 후보입니다.

발화문: INT8 가중치와 문맥 32K, 실행 여유를 합치면 약 2.43 GiB였습니다. 그래서 외부 8GB가 필요하다는 최초 가설을 버리고, 가중치 공급을 분리해 네 클러스터의 유휴를 줄이는 이득이 데이터 이동 비용보다 큰가로 질문을 바꿨습니다. 2.43 GiB에는 INT8 가중치, 문맥 32K의 KV, 실행 여유가 포함됩니다. 명목 용량에 들어간다는 사실만으로 실제 대역폭과 지연이 충분하다고 결론 내리지는 않습니다.

그림 설명 순서: 처음 가설 → 2.43 GiB 용량 계산 → 새 연구 부등식

전환: 이 질문을 두 FPGA의 역할 분리로 구체화했습니다.

예상 질문: Gemma 1B가 4 GB에 들어가는데 왜 외부 8 GB를 검토했는가?

답변 핵심: 외부 8 GB는 1B의 필수 용량이 아니라 더 큰 모델·긴 문맥과 가중치 공급 분리를 위한 조건부 확장 후보입니다.

해석 경계: 2.43 GiB는 용량 모델이며 보드 실측이 아닙니다.

주의할 표현: 외부 8 GB가 Gemma 1B의 필수 용량이라고 말하지 않는다.

## Slide 4: 계산은 K26, 공급은 Memory FPGA 후보 (0:45)

기억할 문장: K26은 연산·제어를, Memory FPGA 후보는 네 채널의 가중치 공급을 맡습니다.

발화문: K26의 네 연산 클러스터와 로컬 큐가 TileJob을 실행합니다. 외부 후보는 네 DDR3L 채널과 네 논리 링크로 가중치를 공급합니다. TileJob의 선호 채널과 링크가 계산 위치와 데이터 위치를 연결합니다. 실선은 이번에 닫은 논리 경로, 점선 GTH·CDC·MIG는 후속 물리 경로입니다. 실선은 RTL에서 작업 ID와 데이터가 이어지는 논리 경로이고, 빨간 물리 경로는 아직 구현하지 않은 GTH 직렬화, 클록 도메인 교차, 패킷, MIG를 뜻합니다.

그림 설명 순서: K26 연산부 → 논리 링크 → Memory FPGA 공급부 → 미구현 물리 경로

전환: 실제 타일이 닫힌 논리 경로를 통과하는지 확인했습니다.

예상 질문: 현재 실제로 구현된 구간과 후보로 남은 구간은 어디인가?

답변 핵심: 작업 수락부터 논리 응답·링크 FIFO·MatVec 결과까지는 닫혔고 GTH·CDC·MIG 물리 경로는 남아 있습니다.

해석 경계: 4채널과 4링크는 후보 구조이며 물리 GTH/MIG는 미구현입니다.

주의할 표현: 논리 폐루프를 물리 GTH·MIG 폐루프로 확대하지 않는다.

## Slide 5: 실제 가중치 타일이 논리 폐루프 RTL을 통과했다 (0:40)

기억할 문장: 대표 Gemma 타일 세 개가 작업 수락부터 결과까지 닫힌 논리 경로를 통과했습니다.

발화문: 작업 수락, DMA 요청, 응답 경계, 논리 링크 FIFO, 작업 ID 결합, MatVec 결과를 하나의 상위 모듈로 연결했습니다. gate_proj, lm_head, o_proj 세 타일이 모두 INT32 기준과 일치했습니다. 이 실제 타일 시험은 1클러스터·1채널·S0이며, S3 작업 소유권 시험은 별도의 합성 스케줄러 시험 입력입니다. 응답은 MIG가 아니라 시험벤치 경계에서 주입했습니다. 세 타일의 수락 사이클은 5, 89, 173이고 결과 사이클은 88, 172, 256입니다. 이 기능 시험은 1클러스터 S0이므로 작업 훔치기 성능 증거와 분리합니다.

그림 설명 순서: 데이터 흐름 영상 → 세 타일 사이클 → 3/3 일치 → 시험 범위

전환: 이제 동적 재분배가 필요한 정적 큐 문제를 보겠습니다.

예상 질문: 실제 Gemma가 FPGA에서 실행됐다고 볼 수 있는가?

답변 핵심: 아닙니다. 실제 가중치 타일 세 개의 논리 RTL 산술만 확인했으며 전체 Gemma 추론은 실행하지 않았습니다.

해석 경계: GTH·CDC·MIG 물리 타이밍과 작업 훔치기 결합 실험은 포함하지 않습니다.

주의할 표현: 세 타일 일치를 전체 모델 실행·정확도로 확대하지 않는다.

## Slide 6: 정적 로컬 큐는 지역성을 지키지만 작업대를 놀린다 (0:40)

기억할 문장: 정적 큐의 문제는 전체 자원 부족보다 작업 쏠림입니다.

발화문: 각 클러스터가 자기 큐만 처리하면 가중치 지역성은 좋습니다. 하지만 C0에 작업이 몰리면 C1부터 C3이 비어 있어도 도와주지 못하고, 뒤쪽 TileJob의 p95와 p99가 길어집니다.

그림 설명 순서: C0의 긴 대기열 → C2·C3 유휴 → 지역성과 부하 균형의 충돌

전환: 빈 작업대가 일을 가져오는 조건을 추가했습니다.

예상 질문: 정적 큐가 지역성을 지키면서도 왜 꼬리 지연을 만드는가?

답변 핵심: 정적 소유권 때문에 한 큐가 밀려도 빈 클러스터가 돕지 못해 뒤쪽 작업의 대기가 길어집니다.

해석 경계: 이 화면은 개념이며 수치는 뒤의 동일 시드 실험에서 제시합니다.

주의할 표현: 정적 큐를 모든 조건에서 나쁜 정책이라고 일반화하지 않는다.

## Slide 7: 이득이 이동 비용보다 클 때만 훔친다 (0:40)

기억할 문장: S3 지역성 인식 작업 훔치기(Work Stealing)는 이동 비용을 서비스 시간에 직접 반영합니다.

발화문: 유휴 클러스터가 실행 가능한 작업을 찾고, 기다림 감소에서 데이터 이동 비용을 뺀 값이 양수일 때만 작업 소유권을 옮깁니다. S2는 가장 오래된 작업을 가져오지만 S3는 지역성 비용을 포함해 원격 이동량을 줄입니다. S3 지역성 인식 작업 훔치기는 가중치뿐 아니라 활성값, 부분합, 링크 묶음 불일치 비용도 포함합니다. 추가 전송량은 사후 통계가 아니라 서비스 시간에 직접 부과됩니다.

그림 설명 순서: 유휴 감지 → 피해 큐 탐색 → 이동 비용 계산 → 소유권 이동 → 완료

전환: 정책을 실제 Gemma 형상의 작업으로 바꾸겠습니다.

예상 질문: S3는 어떤 기준으로 작업을 훔치지 않기로 결정하는가?

답변 핵심: 대기 감소 이득이 가중치·활성값·부분합·링크 이동 비용보다 클 때만 소유권을 옮깁니다.

해석 경계: 영상은 정책 상태 전이이며 최적성이나 보드 타이밍을 뜻하지 않습니다.

주의할 표현: 정책 점수를 최적성 증명이나 보드 타이밍으로 말하지 않는다.

## Slide 8: Gemma 그래프를 의존성 있는 802개 TileJob으로 변환 (0:45)

기억할 문장: 그래프 형상과 단계·토큰 의존성, 네 초기 배치를 명시적으로 모델링했습니다.

발화문: 7,837개 그래프 노드에서 토큰당 183개 밀집 투영을 찾고 N≤1024 기준으로 802 TileJob을 만들었습니다. q/k/v 다음 o, MLP, 다음 계층, lm_head 뒤 다음 토큰 순서를 지켰습니다. 32토큰은 25,664 TileJob입니다. 네 초기 배치를 비교해 처음부터 잘 나눈 효과와 나중에 훔친 효과를 구분했습니다.

그림 설명 순서: 7,837개 노드 → 183개 투영 → 802개 TileJob → 의존성 사슬

전환: 같은 작업과 시드에서 정책만 바꾼 실행을 보겠습니다.

예상 질문: 183개 투영과 802개 TileJob은 어떻게 다른가?

답변 핵심: 183은 그래프의 밀집 투영 수이고 802는 이를 N≤1024·전체 K 범위로 나눈 하드웨어 작업 수입니다.

해석 경계: 802와 25,664는 그래프 형상과 명시한 타일 분할 규칙의 결과입니다.

주의할 표현: 그래프 작업 수를 실제 FPGA 실행 횟수라고 말하지 않는다.

## Slide 9: 동일 작업·동일 시드에서 S1과 S3만 바꿨다 (0:45)

기억할 문장: 실행 사건 CSV의 같은 작업을 대기·원격 준비·연산 구간으로 비교합니다.

발화문: 합성 편향 부하의 같은 1,000개 작업과 같은 시드에서 정책만 바꿨습니다. 대표 작업 훔치기 세 건을 확대해 도착부터 배치까지의 대기, 원격 복사, 연산, 완료를 색으로 구분했습니다. 모든 정책은 완료 ID와 작업 해시가 같고 중복과 누락이 없습니다. J79, J90, J100의 숫자는 원본 사건 CSV에서 가져왔습니다. 구간 폭은 가독성을 위해 압축했지만 상자 안 사이클, 클러스터, 작업 ID는 원본과 같습니다.

그림 설명 순서: 왼쪽 S1 → 오른쪽 S3 → J79·J90·J100 → 색 범례

전환: 다섯 시드를 짝지은 꼬리 지연 결과를 보겠습니다.

예상 질문: 이 타임라인은 실제 Gemma 실행인가?

답변 핵심: 아닙니다. 같은 합성 편향 작업 1,000개와 같은 시드에서 정책만 바꾼 분석 사건입니다.

해석 경계: 분석 사건이며 GTH·DDR 물리 사이클이 아닙니다.

주의할 표현: 분석 사건을 DDR·GTH 물리 사이클로 부르지 않는다.

## Slide 10: 효과는 부하 불균형과 초기 배치에 조건부 (0:45)

기억할 문장: 작업 훔치기는 남은 불균형이 큰 조건에서만 효과가 있습니다.

발화문: 합성 편향 부하에서 S3는 S1보다 TileJob p95를 19.13%, p99를 18.71% 줄였습니다. Gemma 형상에서는 기존 산술 배치가 p95를 0.28% 늘렸고 채널 친화 배치에서는 19.79% 줄였습니다. 보편적 우월성이 아니라 효과 조건을 분리한 결과입니다.

그림 설명 순서: 합성 부하 p95·p99 → Gemma 기존 배치 → 채널 친화 배치

전환: 이득과 함께 새로 생긴 비용을 보겠습니다.

예상 질문: 왜 Gemma 배치에 따라 p95 결과의 방향이 달라지는가?

답변 핵심: 작업 훔치기는 초기 배치 뒤에 남은 불균형만 줄이므로 기존 산술 배치와 채널 친화 배치의 결과 방향이 달라집니다.

해석 경계: p95와 p99는 의존성 해제 뒤 TileJob 완료 분포이며 사용자 응답 지연이 아닙니다.

주의할 표현: TileJob p95를 사용자 요청 지연으로 부르지 않는다.

## Slide 11: 작업 훔치기는 병목을 없애지 않고 이동시킨다 (0:40)

기억할 문장: 비교 기준을 분리하면 꼬리 지연 감소와 이동량 감소가 완료시간 개선을 보장하지 않음을 볼 수 있습니다.

발화문: S3 대 S1에서 p95는 19.13% 줄었습니다. S3 대 S2에서 원격 가중치는 35.49% 줄었지만 완료시간은 0.01% 늘어 사실상 같았습니다. 첫 비교는 정적 큐 효과, 두 번째는 지역성 점수 효과입니다. 왼쪽은 정적 S1과 S3를 비교하고 오른쪽은 가장 오래된 작업 우선 S2와 S3를 비교합니다. 기준이 다르므로 세 수치를 하나의 연속 인과식으로 읽으면 안 됩니다.

그림 설명 순서: S1 대비 p95 → S2 대비 원격 가중치 → 완료시간 → 기준 차이

전환: 이제 전체 구조가 K26 로컬 기준선을 이기는지 보겠습니다.

예상 질문: 세 수치의 비교 기준이 서로 다른 이유는 무엇인가?

답변 핵심: S1 비교는 정적 큐 대비 재분배 효과를, S2 비교는 단순 훔치기 대비 지역성 점수 효과를 분리합니다.

해석 경계: 서로 다른 기준의 수치를 하나의 인과식으로 해석하지 않습니다.

주의할 표현: 서로 다른 기준의 수치를 하나의 연속 인과식으로 묶지 않는다.

## Slide 12: 이번 민감도에서는 K26 로컬이 우선이다 (0:45)

기억할 문장: Gemma 1B의 기본 선택은 이번 분석 민감도에서 K26 로컬입니다.

발화문: 대표 중앙 조건에서 K26 로컬 9.6 GB/s는 약 24.6M사이클, 외부 4채널 6.4 GB/s는 약 120.6M사이클이었습니다. 모든 시험 범위에서 외부 후보가 로컬을 이기지 못했습니다. 외부 구조는 더 큰 모델, 더 긴 문맥, 실제 로컬 경합이 계측될 때 재평가해야 합니다. 4.8, 9.6, 14.4 GB/s의 로컬과 3.2, 6.4, 12.8 GB/s의 외부 민감도를 비교했습니다. 전 범위에서 외부 후보가 로컬 완료시간을 이기지 못했습니다.

그림 설명 순서: K26 로컬 → 외부 후보 → 시험 대역폭 범위 → 채택 보류 조건

전환: 물리 후보를 어디까지 구체화했는지 보겠습니다.

예상 질문: K26 로컬이 이겼는데 외부 구조 연구가 왜 의미 있는가?

답변 핵심: 이번 1B 조건은 K26 로컬이 우선이지만 더 큰 모델·긴 문맥·실측 로컬 경합에서는 외부 후보를 다시 평가할 가치가 있습니다.

해석 경계: 분석 모델의 민감도이며 보드 측정이나 주파수 환산값이 아닙니다.

주의할 표현: 민감도 결과를 보드 실측이나 미래 모든 조건으로 일반화하지 않는다.

## Slide 13: KiCad 결과는 참조 라우팅 쿠폰이다 (0:45)

기억할 문장: 쿠폰은 경계 링크·기준 클록·DDR3L 한 슬라이스의 물리 질문을 구체화합니다.

발화문: 범용 경계 커넥터, DDR3L x16 한 슬라이스, GTH/기준 클록 일부 배선을 실제 KiCad 객체로 만들었습니다. 풋프린트 29개와 배선 20개, 선언된 쿠폰 범위의 ERC/DRC 0을 확인했지만 전체 116개 신호망 중 55개가 미배선이고 SI/PI/PDN도 남았습니다. 화면의 J1·J2는 특정 K26나 Memory FPGA BGA 핀 배치가 아니라 범용 경계입니다. 미배선 55개와 SI·PI·PDN 관문 때문에 제작 대상으로 사용할 수 없습니다.

그림 설명 순서: 전체 KiCad 렌더 → 경계 링크 → 기준 클록 → DDR3L 쿠폰 → 제작 금지

전환: 이제 현재 한계와 다음 검증 순서를 분명히 하겠습니다.

예상 질문: 이 PCB 자료로 바로 제작할 수 있는가?

답변 핵심: 아닙니다. 범용 경계와 일부 GTH·기준 클록·DDR3L 배선을 확인한 참조 쿠폰이며 미배선·SI/PI/PDN 과제가 남았습니다.

해석 경계: REFERENCE COUPON이며 NOT FOR FABRICATION입니다.

주의할 표현: 쿠폰 ERC/DRC 0을 전체 보드 제작 준비 완료로 말하지 않는다.

## Slide 14: 한계와 향후 탐구 방향 (0:25)
