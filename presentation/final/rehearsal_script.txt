[03 | 0:45] Gemma 3 1B는 4GB 안에 들어갔다—그래서 질문을 바꿨다
처음에는 외부 8GB가 모델을 담기 위해 필요하다고 생각했습니다. 그런데 실제 용량을 계산해 보니 Gemma 3 1B는 K26의 4GB 안에도 들어갔습니다. 그래서 질문을 바꿨습니다. 외부 메모리가 더 큰 창고이기만 해서는 의미가 없습니다. 가중치 공급을 분리해서 얻는 이득이 데이터를 옮기는 비용보다 커야 합니다.
→ 이 질문을 두 장치의 역할 분리로 구체화했습니다.

[04 | 0:50] K26은 계산하고, Memory FPGA는 가중치를 공급한다
K26은 운영체제와 제어, 네 연산 클러스터, 로컬 대기열, MatVec를 맡습니다. Memory FPGA는 가중치 저장과 네 메모리 채널, 채널 선택, 링크 전송을 맡습니다. 각 연산 타일에는 계산할 위치와 가중치가 가까운 채널을 함께 기록합니다. 네 클러스터와 네 채널은 구조 분석 범위이고, 실제 가중치 MatVec 시험은 한 클러스터·한 채널·정적 경로에서 수행했습니다. 점선의 직렬 링크와 메모리 제어는 실제 보드에서 더 구현해야 합니다.
→ 이 구조가 기존 접근과 어떻게 다른지 비교하겠습니다.

[05 | 0:35] 메모리 용량만 늘리지 않고, 작업 배치와 데이터 위치를 함께 설계했다
기존 연구는 연산량, 메모리 대역폭, 정적 배치를 각각 다뤘습니다. 이 연구는 실제 Gemma 그래프에서 작업을 만들고, 초기 배치와 데이터 이동 비용을 함께 비교해 외부 메모리가 유효한 조건을 찾았습니다.
→ 이제 실제 가중치로 확인한 MatVec 범위를 보겠습니다.

[06 | 0:45] 실제 Gemma 가중치를 MatVec RTL에서 검증했다
실제 Gemma 파일의 output projection, gate projection, lm head에서 16 곱하기 4 크기의 가중치 타일을 하나씩 추출했습니다. 각 타일을 대칭 INT8로 바꾸고 같은 입력으로 소프트웨어 INT32 기준값을 계산했습니다. 그 값을 16 곱하기 4 MatVec RTL 결과와 비교했더니 세 타일이 모두 정확히 일치했습니다. 여기까지는 산술 검증입니다. 실제 DDR에서 읽거나 두 FPGA 사이를 전송한 성능까지 확인한 것은 아닙니다.
→ 정확한 산술만으로는 고정 배정에서 생기는 유휴 문제를 해결할 수 없습니다.

[07 | 0:30] 고정 배정은 데이터를 가까이 두지만 작업을 고르게 나누지 못한다
고정 로컬 큐, S1은 각 작업대 앞에 고정된 대기 줄을 둔 것과 같습니다. 가중치를 가까이 둘 수 있지만 C0에 일이 몰리면 C2와 C3가 비어 있어도 돕지 못합니다. 그래서 평균보다 마지막 작업과 p95·p99 꼬리 지연이 길어질 수 있습니다.
→ 빈 작업대가 이득이 있는 일만 가져오도록 바꿨습니다.

[08 | 0:40] 빈 연산기가 이득이 있는 작업만 가져온다
지역성 인식 작업 재배분, 영어로 locality-aware work stealing은 빈 작업대가 옆 줄의 일을 가져오는 방식입니다. 먼저 유휴 연산기를 찾고, 가져올 작업의 기다림 감소와 가중치·활성값 이동 비용을 비교합니다. 이득이 더 클 때만 작업을 옮깁니다. Work Stealing은 연구의 목적이 아니라 제한된 연산 자원을 활용하기 위한 수단입니다.
→ 이 정책을 실제 Gemma 작업 단위로 바꾸겠습니다.

[09 | 0:35] Gemma 그래프를 802개 연산 타일로 나눴다
실제 Gemma ONNX 그래프의 7,837개 노드에서 토큰마다 실행되는 183개 행렬 연산을 찾았습니다. 큰 행렬을 출력 방향으로 나누면 802개 연산 타일이 됩니다. 이어서 질의·키·값, 출력 투영, 게이트·상향, 하향, 다음 계층의 보수적 단계 의존 규칙을 모델에 부여했습니다. 32토큰에서는 25,664개 연산 타일입니다.
→ 이제 같은 작업에서 배정 방식만 바꾼 대표 사례를 보겠습니다.

[10 | 0:45] 같은 작업에서 고정 배정과 작업 재배분만 바꿨다
작업을 한쪽에 치우치게 만든 실험에서 작업 목록과 초기 배치, 자원 조건은 그대로 두고 배정 방식만 바꿨습니다. 대표 연산 타일은 고정 배정에서 C0 대기열에 오래 남지만, 작업 재배분에서는 비어 있던 C2로 옮겨집니다. 대기는 줄어들고 대신 원격 가중치 이동 구간이 추가됩니다. 작업 ID가 중복되거나 사라지지 않는지도 함께 확인했습니다.
→ 이 변화가 전체 분포에서는 언제 효과적인지 보겠습니다.

[11 | 0:45] 작업이 치우친 경우에만 재배분이 효과적이었다
작업을 한쪽에 치우치게 만든 실험에서는 고정 배정보다 p95가 19.13%, p99가 18.71% 줄었습니다. 하지만 Gemma 형상에서는 기존 초기 배치가 p95를 0.28% 늘렸고, 메모리 채널을 고려한 초기 배치에서는 19.79% 줄였습니다. 즉 스케줄링만 따로 떼어 항상 좋다고 말할 수 없고, 처음 데이터를 어디에 놓았는지와 함께 봐야 합니다.
→ 꼬리 지연을 줄인 대가가 무엇인지 이어서 보겠습니다.

[12 | 0:40] 유휴 연산은 줄었지만 데이터 이동이 새로운 비용이 됐다
고정 배정과 비교하면 지역성 인식 재배분의 p95는 19.13% 줄었습니다. 반면 무제약 재배분과 비교하면 원격 가중치는 35.49% 줄었지만 마지막 완료시간은 0.01% 늘었습니다. 앞의 수치는 고정 배정 대비 효과이고 뒤의 두 수치는 재배분 방식끼리의 비교입니다. 서로 다른 기준이므로 하나의 인과효과처럼 연결하지 않습니다.
→ 이 비용까지 포함해 외부 메모리 채택 조건을 보겠습니다.

[13 | 0:55] 현재 가정에서는 K26의 로컬 메모리 경로가 더 유리했다
유효 메모리 대역폭과 예상 완료 사이클을 같은 축에서 비교했습니다. K26 로컬 경로는 4.8에서 14.4 GB/s, 외부 4채널 경로는 3.2에서 12.8 GB/s로 조건을 바꿨습니다. 시험한 범위에서는 두 곡선이 만나지 않았고, 가운데 조건도 24.6M 대 120.6M사이클이었습니다. 따라서 이 조건만 놓고 보면 외부 Memory FPGA를 채택할 이유는 없습니다. 더 큰 모델이나 긴 문맥, 실제 로컬 메모리 경합이 생겼을 때 다시 확인해야 합니다.
→ 이제 현재 한계와 실제 하드웨어로 이어갈 순서를 말씀드리겠습니다.

[14 | 0:35] 다음 단계는 분석 모델을 실제 하드웨어 경로로 닫는 것이다
